## Key Learnings

### What is Witness?
- Witness is a structure with 3 optional fields:
    - `lock`: signature data for the lock script (e.g., Secp256k1 signature = 65 bytes)
    - `input_type`: data passed to the type script on input cells
    - `output_type`: data passed to the type script on output cells
- Witnesses are indexed parallel to inputs — `witnesses[0]` corresponds to `inputs[0]`
- A placeholder witness (65 zero bytes) is used during fee estimation *before* the real signature is available

```
WitnessArgs {
    lock: Some(vec![0u8; 65])   // 65-byte placeholder for Secp256k1 signature
    input_type: None
    output_type: None
}
```

### Off-chain Rust SDK: ckb-sdk
- `CkbRpcClient` is the main entry point for talking to a CKB node via JSON-RPC
- The SDK has layered abstractions for building transactions off-chain:

| Layer | Type | Role |
|---|---|---|
| Signing | `SecpCkbRawKeySigner` | Signs the tx hash with a private key |
| Unlocking | `SecpSighashUnlocker` | Knows how to build the Witness for secp256k1 |
| Fee | `CapacityBalancer` | Collects input cells and covers the fee |
| Building | `CapacityTransferBuilder` | Assembles the full transfer transaction |

- `ScriptId::new_type(SIGHASH_TYPE_HASH)` is how we reference the system secp256k1 lock script from off-chain code — same concept as `ccc.KnownScript.Secp256k1Blake160` in TypeScript/CCC
- Private key → `secp256k1::SecretKey` → `SecpCkbRawKeySigner` → signs transaction

### Rust Error Handling Patterns
```rust
// Pattern 1: double-? with ok()
// get_block_by_number returns Result<Option<Block>>
// .ok() turns Result into Option (errors become None)
// first ? handles Option from ok(), second ? handles inner Option
let block = client.get_block_by_number(n.into()).ok()??;

// Pattern 2: explicit match — same result, more readable
match client.get_block_by_number(n.into()) {
    Ok(Some(block)) => Some(block.header.inner.timestamp.into()),
    _ => None, // covers both Err and Ok(None)
}
```
