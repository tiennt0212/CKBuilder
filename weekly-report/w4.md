## Key Learnings

### Phase 1 Review Highlights
- **Cell model recap**: every piece of state on CKB is a Cell with `capacity`, `lock`, `type`, and `data` fields
- **Lock vs Type script**: lock script controls ownership/spending, type script enforces state transition rules
- **Witness structure**: indexed parallel to inputs; lock field carries the signature (e.g., 65-byte Secp256k1 placeholder during fee estimation)
- **Off-chain SDK layers** (Rust): `CapacityTransferBuilder` → `CapacityBalancer` → `SecpSighashUnlocker` → `SecpCkbRawKeySigner`

### Frontend Framework Design
- Chose a component-based architecture to isolate CKB-specific logic from UI rendering
- Key views planned:
  - **Wallet Panel**: connect/disconnect, display address and CKB balance
  - **Cell Explorer**: list live cells owned by the connected wallet
  - **Transaction Builder**: input/output cell composer with capacity and data fields
  - **Script Inspector**: display lock/type script hashes and args for any cell
- State management layer stubbed out with placeholder data — ready to be replaced with real CKB RPC responses
