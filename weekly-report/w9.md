## Key Learnings

### Product framing shapes everything downstream
FiberGate started as a managed, multi-tenant gateway concept and was deliberately
pivoted on day one to a self-hosted, single-tenant, open-source framework — driven by
the hackathon's own "infrastructure only, not a product" rule. That single decision
cascaded into simpler auth (one shared secret, no per-client keys), a single-admin
dashboard (no user/role system), and plain PostgreSQL over a heavier self-hosted
Supabase stack. Framing the product correctly early saved a lot of rework later.

### Real-node verification catches what documentation review can't
Several "looked correct on paper" assumptions only broke when actually run against a
live `fnn` node — the `0.0.0.0`-is-public bind classification, `.env` `$`-character
corruption, and the `ckb-cli` key export format mismatch all produced misleading
errors (e.g., a decrypt failure that read like a wrong password, not a format
mismatch). Treating "it matches the docs" as insufficient and verifying live against
a running node paid off repeatedly.

### WebSocket subscriptions vs. polling for state detection
Moving invoice-status detection from a 10s poll loop to a `subscribe_store_changes`
WebSocket subscription (with the poller kept as a 30s fallback, not removed) cut
detection latency from up to 10s down to seconds — while being honest that this RPC
isn't officially scoped by the Fiber team for this use case, hence keeping the
fallback rather than fully committing to it.
