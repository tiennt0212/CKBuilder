## Key Learnings
### CCC Hook Decomposition
- **`useCcc()` vs `useSigner()`**: `useCcc()` exposes the full connector context (wallet name, open/disconnect, signerInfo). `useSigner()` is a shortcut that returns `signerInfo?.signer` — use it when only the signing capability is needed.
- **Feature hooks pattern**: Placing hooks under `features/<domain>/use<Hook>.ts` keeps domain logic co-located and prevents components from accumulating async state management code.

### CKB Transaction Construction with CCC
- **`tx.completeFeeBy(signer)`**: Single call that performs coin selection, calculates the fee, and adds a change output — removing the need to manually manage UTXOs.
- **Pure lib functions**: Separating `buildTransferTx` from the hook means the transaction logic can be unit-tested independently from wallet connection state.

### State Machine for Async Flows
- Modeling the transfer lifecycle as a `TransferStatus` union type (`"idle" | "building" | "signing" | "sending" | "done" | "error"`) makes it straightforward to reflect each stage in the UI and handle errors at any step without duplicating state flags.
